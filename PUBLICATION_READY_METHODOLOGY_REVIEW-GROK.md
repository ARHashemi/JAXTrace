## Octree Construction
The structure qualifies as a **linear octree** (also "hashed" or "prefix-coded octree"), not a pointer-based tree traversal. Construction sorts element centroids by Morton/Hilbert code (O(M log M)), then scans linearly to form leaves (group until capacity=256 exceeded or prefix jumps), building implicit hierarchy via common-code prefixes. Prefix table maps query Morton prefixes (top table_depth=7 bits) to leaf ranges for O(1) lookup + tiny linear scan (avg 1-3 leaves). [d-nb](https://d-nb.info/1217140409/34)

Leaves **are** neighbor collections: Sequential SFC sorting ensures spatial locality, so leaves cluster geometrically similar elements (e.g., same octant or refinement level). No full tree build/traversal needed—GPU-friendly, avoids divergence. This matches your mesher (octree-refined Kuhn tets) perfectly; call it "Morton prefix-sum octree" for precision.
